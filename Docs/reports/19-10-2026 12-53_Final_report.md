## What exists now
- `cli.py` — CLI pipeline: claim → LangGraph (search → 5 parallel read+critique branches → verdict) → printed verdict + source table.
- `app/main.py` — FastAPI: `GET /` (UI), `POST /check` (SSE: progress / finding / notice / result / error events), 3-minute run budget, MCP servers + Groq client started once at app startup.
- `app/graph.py` — LangGraph: claim passthrough → search → `Send` fan-out (max 5, domain-deduped) → read+critique per branch → summarize (verdict from formula, explanation from LLM) → conditional single retry with LLM-refined query.
- `app/llm.py` — the ONLY LLM access point: Groq, JSON mode + Pydantic validation + 1 JSON retry, semaphore(2), remaining-tokens wait, 429/`retry-after` backoff (max 3), usage logging.
- `app/verdict.py` — pure scoring formula (spec Section 9), unit tested.
- `app/nodes.py` — extract claims (≤3), search, read (evidence-wired), critique (independent, quote-verified), rewrite query.
- `mcp_servers/` — `search_server.py` (FastMCP + ddgs, capped retries), `evidence_server.py` + `evidence_core.py` (passages, credibility tiers, dates, quote check).
- `static/index.html` — vanilla JS UI: live progress, per-claim result cards, credibility bars, notices, error states.
- `tests/` — 51 offline tests (no API), all passing in ~1.3s.
- `Docs/reports/` — one timestamped report per milestone (M1–M6) with bugs found, token usage, and spec deviations.
